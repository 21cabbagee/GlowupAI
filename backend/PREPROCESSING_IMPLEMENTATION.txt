OVERVIEW
--------
Implemented a comprehensive image preprocessing pipeline to normalize lighting
and quality variations before skin analysis. This reduces inconsistent scores
caused by different lighting conditions, compression artifacts, and color
temperature variations.

PROBLEM SOLVED
--------------
- Inconsistent analysis scores due to lighting variations
- False changes detected from compression differences
- Color temperature variations affecting redness measurements
- Different image qualities producing unreliable metrics

SOLUTION IMPLEMENTED
--------------------
Multi-stage preprocessing pipeline that normalizes images before analysis:

1. White Balance Correction
   - Normalizes color temperature using Gray World algorithm
   - Fixes warm/cool lighting variations
   - Ensures consistent color representation

2. CLAHE (Contrast Limited Adaptive Histogram Equalization)
   - Improves local contrast for better skin detail visibility
   - Particularly effective for skin texture analysis
   - Avoids over-amplification of noise

3. Denoising (Non-Local Means)
   - Reduces compression artifacts and camera noise
   - Preserves edges and skin texture details
   - Improves metric consistency

4. Standardized Resizing
   - Resizes all images to consistent 512x512 dimensions
   - Uses high-quality Lanczos interpolation
   - Ensures uniform analysis input

---------------------
New environment variables for controlling preprocessing:

1. SKINPROOF_ENABLE_PREPROCESSING
   - Default: 1 (enabled)

   - Controls whether preprocessing is applied before analysis
   - Recommended: Keep enabled (1) in production

   - Default: 0 (checks enabled)
   - Values: 0 (checks enabled) | 1 (checks disabled)

FALLBACK BEHAVIOR
-----------------
If OpenCV is not available:
- System automatically falls back to PIL-based preprocessing
- Provides basic normalization (resizing, format conversion)
- Less comprehensive than OpenCV pipeline but ensures system continues working
- Logs warning message when fallback is used

If preprocessing fails entirely:
- System falls back to original image
- Analysis continues with unprocessed image
- Error is logged for monitoring
- No interruption to service

INTEGRATION
-----------
Preprocessing is automatically applied in the analysis pipeline:

1. User submits photo via API
2. Photo passes quality checks (capture.py)
3. Preprocessing is applied (NEW - preprocessing.py)
   - White balance correction
   - CLAHE enhancement
   - Denoising
   - Standardization
4. Preprocessed image is analyzed (metrics.py)
5. Results returned to user

The original photo is PRESERVED and not modified. Preprocessing only affects
the image used for analysis, not the stored photo.
