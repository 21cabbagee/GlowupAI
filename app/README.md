# GlowUp AI — Android app

Setup notes for building and running this module (`:app`, package
`com.glowup.ai`). For what the app is and its overall status, see the repo
root `README.md`, `QUICK_SUMMARY.md`, and `ANDROID_PLAN.md`.

## Requirements

- **Android SDK.** `compileSdk`/`targetSdk` 37, `minSdk` 24. You need at
  least: `platform-tools`, `platforms;android-37`, `build-tools;37.0.0`,
  `cmdline-tools;latest`, with licenses accepted.
- **JDK 25.** `app/build.gradle.kts` sets `kotlin { jvmToolchain(25) }` and
  targets **bytecode 17** (`compileOptions` / `sourceCompatibility` /
  `targetCompatibility` = `JavaVersion.VERSION_17`). This is deliberate, not
  a mismatch: this machine only has JDK 25 installed, and Gradle's
  toolchain auto-download (which would normally fetch a JDK 17) is blocked
  by the network gateway (`services.gradle.org` and GitHub-hosted asset
  downloads return 403 here). Pointing the toolchain at the already-installed
  JDK 25 and letting `kotlinc`/`javac` emit JVM 17 bytecode avoids needing a
  toolchain download at all. If your machine can reach
  `services.gradle.org`, a JDK 17 toolchain would also work, but there is no
  need to change this for a normal build.
- **`local.properties`.** Generated by Android Studio / the SDK manager,
  git-ignored (see the root `.gitignore`), and not checked in. It just needs
  one line:
  ```
  sdk.dir=<path to your Android SDK>
  ```
  If it's missing, open the project in Android Studio once and let it
  regenerate the file, or create it by hand.

## Network note: repo1.maven.org is blocked here

This machine sits behind a secure web gateway that returns HTTP 403 for
`repo1.maven.org` (and `services.gradle.org`). Because of that,
`settings.gradle.kts` at the repo root lists **Google's GCS-hosted Maven
Central mirror** (`https://maven-central.storage-download.googleapis.com/maven2/`)
ahead of `mavenCentral()` in both `pluginManagement` and
`dependencyResolutionManagement`. It serves identical artifacts and is
reachable from this network; `mavenCentral()` is kept as a fallback for
machines without this restriction. If you build on a machine where
`repo1.maven.org` is reachable, you don't need to do anything — the mirror
is just tried first and both are declared. If dependency resolution fails
with a 403 for `repo1.maven.org`, that's this restriction; don't remove the
mirror entry to "fix" it.

## Firebase (`google-services.json`)

Firebase Auth/Analytics/Crashlytics require `app/google-services.json`,
generated from the Firebase console for the `glowup-ai` project (see
`ANDROID_PLAN.md` Phase 1.1 — this is a human-only step, it needs a
console login). **This file is not present by default in a fresh checkout,
and the build tolerates that on purpose:** `app/build.gradle.kts` checks
whether the file exists and only applies the
`com.google.gms.google-services` and `com.google.firebase.crashlytics`
Gradle plugins if it does. Without it, the build still succeeds and the
Firebase *dependencies* still compile — Firebase just won't initialize at
runtime, and Gradle prints a loud warning during configuration saying so.
Add the real file at `app/google-services.json` once the Firebase project
exists to turn this on.

## Release signing (`keystore.properties`)

Copy `app/keystore.properties.example` to `app/keystore.properties` (this
filename is git-ignored) once a real upload keystore exists:

```bash
keytool -genkey -v -keystore release.keystore -alias glowup-release \
  -keyalg RSA -keysize 2048 -validity 10000
```

then fill in `storeFile`, `storePassword`, `keyAlias`, `keyPassword` in
`keystore.properties`. Without this file, the `release` (and `staging`)
build types fall back to **debug signing** with a build-time warning — that
is enough to keep the build green for everyone else working in this repo,
but a release artifact signed that way must never be distributed.

## Build types and API base URL

Three build types, each with its own `BuildConfig.API_BASE_URL`:

| Build type | `API_BASE_URL` | Notes |
| --- | --- | --- |
| `debug` | `http://10.0.2.2:8000/api/` | Points at a backend running on your host machine's `localhost:8000`, reachable from the emulator at `10.0.2.2`. |
| `staging` | `-PSTAGING_API_BASE_URL=...` Gradle property, else a placeholder (`https://staging.glowup.example.invalid/api/`) | Set the property once a staging backend is deployed (see root `DEPLOY.md`). The placeholder is intentionally invalid so it can't be mistaken for a working endpoint. |
| `release` | `-PRELEASE_API_BASE_URL=...` Gradle property, else the same kind of placeholder (`https://api.glowup.example.invalid/api/`) | Same idea, for the production backend. |

Pass the property at build time, e.g.:

```bash
./gradlew :app:assembleStaging -PSTAGING_API_BASE_URL=https://your-staging-host/api/
```

## Running the `glowup_pixel` emulator

An AVD named `glowup_pixel` already exists under
`%USERPROFILE%\.android\avd\glowup_pixel.avd`. To launch it from the
command line (from the Android SDK's `emulator/` directory, or with it on
`PATH`):

```bash
emulator -avd glowup_pixel
```

Or launch it from Android Studio's Device Manager. Once it's running:

```bash
./gradlew :app:installDebug
```

installs the debug build, which will reach a backend on your host machine
at `http://10.0.2.2:8000/api/` if one is running locally (`cd backend &&
uvicorn skinproof.complete_api:app --reload --port 8000`).
